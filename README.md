# Clinical Note ICD-10 Extractor (`note_icd10_extractor`)

A modular, clinical Natural Language Processing (NLP) pipeline designed to extract problem-list entities from unstructured Assessment & Plan (A&P) documentation and map them to standardized ICD-10-CM codes.

Built specifically to handle narrative nuances generated by ambient clinical documentation systems (such as Abridge) and physician charting, the system implements multi-stage normalization (billing tag scrubbing, hedge phrase removal, acronym/colloquial expansion, and token deduplication) alongside a two-tier matching engine.

---

## Architecture & Pipeline Flow

The extraction and matching engine operates in five deterministic stages:

```
[ Unstructured Clinical Note (.txt) ]
                  │
                  ▼
   1. Section Boundary Isolation
      (Regex extraction of "Assessment & Plan" block, terminated by several underscores: "____")
                  │
                  ▼
   2. Entity Extraction & Normalization
      ├─ Billing Tag Scrubbing (e.g., "(CMS/HCC)", "[HCC]")
      ├─ Hedge Phrase Stripping (via hedge_phrases.csv)
      ├─ Punctuation Normalization
      ├─ Clinical Acronym Expansion (via acronym_map.csv)
      └─ Word-order-preserving Token Deduplication
                  │
                  ▼
   3. ICD-10 Registry Filtering
      (Scope constrained to neurology-relevant ICD chapters: G, I, F, Z)
                  │
                  ▼
   4. Two-Stage Matcher Engine
      ├─ Stage 1: Deterministic Token-Subset Filter + Etiology Prioritization
      └─ Stage 2: RapidFuzz Similarity Scorer (Token-Sort & Token-Set Fallback)
                  │
                  ▼
[ Structured Report Table: Candidate Term | ICD-10 Code | Description | Confidence ]
```

## Reference Data Configuration

All clinical domain knowledge is managed through CSV configuration files in `data/`, isolating clinical vocabulary updates from the underlying codebase:

1. **`data/icd10_codes.csv`**: Target registry containing ICD-10 codes and descriptions:
   ```csv
   icd10_code,description
   G47.33,"Obstructive sleep apnea (adult) (pediatric)"
   F03.A0,"Unspecified dementia, mild, without behavioral disturbance, psychotic disturbance, mood disturbance, and anxiety"
   Z86.73,"Personal history of transient ischemic attack (TIA), and cerebral infarction without residual deficits"
   ```

2. **`data/acronym_map.csv`**: Clinical synonyms and abbreviations mapped to target ICD-10 phrasing:
   ```csv
   acronym,expansion
   cva,cerebral infarction
   cerebrovascular accident,cerebral infarction
   osa,obstructive sleep apnea
   tia,transient ischemic attack
   mci,mild cognitive impairment
   ```

3. **`data/hedge_phrases.csv`**: Diagnostic hedging and historical prefixes removed during normalization:
   ```csv
   hedge_phrase
   history of
   hx of
   status post
   s/p
   possibly
   suspected
   ```

## Installation & Setup

### Prerequisites
* Python 3.10+
* Git

### 1. Clone the Repository
```bash
git clone https://github.com/<your-username>/note_icd10_extractor.git
cd note_icd10_extractor
```

### 2. Configure Virtual Environment
* **macOS / Linux:**
  ```bash
  python3 -m venv .venv
  source .venv/bin/activate
  ```
* **Windows (PowerShell):**
  ```powershell
  python -m venv .venv
  .venv\Scripts\Activate.ps1
  ```

### 3. Install Dependencies
```bash
pip install pandas rapidfuzz
```

---

## Usage

1. Place clinical note files (`.txt`) inside the `notes/` directory.
2. Run the pipeline from the project root:
   ```bash
   python scr/main.py
   ```
3. Follow the interactive CLI prompts:
   * Select a note file from the numbered menu.
   * Enter the attending provider name.
4. Review the extracted Assessment & Plan preview and the final left-aligned ICD-10 mapping table.

## Data Privacy & HIPAA Compliance

This repository enforces strict data hygiene to avoid accidental leaks of Protected Health Information (PHI):
* Real clinical `.txt` notes placed inside `notes/` are excluded by `.gitignore` (`notes/*.txt`).
* Directory structure persistence is guaranteed across clones using `notes/.gitkeep`.
* Only synthetic, non-PHI demonstration data (`synthetic_sample.txt`) is tracked in version control.
